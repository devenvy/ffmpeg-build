devenvy/ffmpeg-build uses OpenVINO's native CMake build for its C API, CPU plugin and
IR model frontend as static libraries. GPU/NPU devices, Python, JavaScript,
network model downloads and other model frontends are disabled. Convert
models to OpenVINO IR before using them with this build. CPU threading is
sequential and does not require a system OpenMP or TBB runtime.

The complete native headers and CMake SDK are installed through upstream's
common-library layout. The static dependency closure is obtained from its
own CMake consumer target and copied under packaging archive names without
changing their contents or symbols. A separate ffb-openvino-cpu.ld GROUP script
provides FFmpeg's static closure, including its C++ runtime. The native
libopenvino.a and other SDK archives retain their names and contents.
Upstream generates pkg-config metadata only for shared builds; static C API
consumers receive packaging metadata with the native static interface definition.

The opt-in native shared CPU mode explicitly builds the C/C++
runtime, dynamically loaded CPU plugin and IR frontend. Native plugins.xml
generation is enabled and its relative registry ships beside the libraries.
Its native interface definitions and pkg-config metadata are preserved. The
shared libraries use the system C++ runtime and common unwinder. SDK probes
compile against installed CMake targets and headers, including full CPU/IR
inference, public type bridges and exception ownership. CPU threading remains
sequential. No upstream source or build file is edited.
