2026-10-22: devenvy/ffmpeg-build builds TensorFlow's CPU Graph and Eager C APIs
from source using its native shared owner. GPU, NCCL, Python runtime distribution and dynamically
loaded kernel modules are disabled. No pretrained model is shipped.

The recipe pins Bazel, all fetched repository inputs and its nested LLVM source.
Binary build tools are labelled separately from runtime libraries. A clean build
from engine-captured inputs is tested with both networking and Bazel repository
downloads disabled. Source input records distinguish recipe-generated replay
metadata from upstream checksum pins.

The native Graph/Eager shared library is installed unchanged. Static FFmpeg
integration is not offered: its native alwayslink registration closure cannot
be scoped to one owner through stock FFmpeg's transitive link flags.
Runtime notices follow the actual C API owner closure, including
header-only dependencies. BoringSSL's original OpenSSL/SSLeay terms remain in
the aggregate; the recipe therefore uses the existing LGPLv3/nonfree gate.

Upstream symbols and export policies remain unchanged. Incompatible combinations
require supported native configurations or explicit composition restrictions.
Shared mode preserves the upstream native export policy, including its public
TF/TFE C++ compatibility bridges, in one monolithic Graph/Eager library.
Its compiler-runtime selection remains native; no upstream toolchain helper is edited.

DUCC's FFT subset selects its BSD alternative; zstd and Highway select BSD;
JsonCpp selects MIT. Their full source notices and the applicable per-file
notices are preserved. Tool-input notices do not change the binary licence gate.

Compiler runtime code uses GPL-3.0-or-later WITH GCC-exception-3.1. Pinned GCC
8.4.0 upstream texts supplement the binary sysroot's missing package manifest
and distributor notices; the original notice-coverage gap remains documented.
